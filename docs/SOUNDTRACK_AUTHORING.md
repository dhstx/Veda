# Preparing the first soundtrack family.

Start with one related musical identity for calm space, motion, uncertainty, combat, escape, and relief. The engine uses aligned layers; it does not make independently generated full songs synchronize automatically.

## First practical workflow.

1. Create a coherent instrumental piece or source material with a science-fiction atmosphere.
2. Export stems and open them in an audio editor or DAW.
3. Choose one steady tempo and one common loop region. The demo uses 96 BPM, 4/4, four bars: 10 seconds.
4. Prepare an atmosphere bed plus optional motion, tension, combat, escape, and relief layers. Some Suno exports will need editing, removal of bleed, or rearrangement to make these useful.
5. Export every stem from the same start to the same end, even if some contain intentional silence. Do not trim leading silence independently.
6. Use stereo 48,000 Hz PCM16 or IEEE float32 WAV, ordinary RIFF. This starter does not accept 24-bit PCM, WAVE_EXTENSIBLE, mono, MP3, or mismatched sample rates.
7. Listen across the loop seam and across every gain combination you intend to use.

A sustained pad should not end in a click, and separated stems should not accumulate unexpected clipping when combined. Leave generous headroom; matching key and tempo alone does not establish musical compatibility.

## Folder format.

Create a folder such as `assets/soundtracks/private/the-void/` and put `soundtrack.json` and your WAVs inside it. That private folder is ignored by Git. The app can load soundtrack folders anywhere on your computer; they do not have to live inside the repo.

Copy `assets/soundtracks/demo-void/soundtrack.json` as the starting manifest. Use a new id and title, then update paths, tempo, meter, bar count, and gains. Every state must specify every layer, including a zero gain for silent layers.

The first layer is the base layer. Drama adjusts the other layers. Keep these generic state names exactly as supplied: `CalmSpace`, `Travel`, `Uncertain`, `Combat`, `Escape`, `Relief`.

The schema is in `schemas/soundtrack.schema.json`. Runtime validation is authoritative and also checks WAV bytes, alignment, and the decoded memory budget.

## Length calculation.

The required frame count is:

`round(48000 × 60 ÷ tempoBpm × beatsPerBar × loopBars)`

At 96 BPM, 4 beats per bar, and 4 loop bars, every stem has 480,000 stereo frames. The complete file has 960,000 sample values. Export each stem to exactly that range.

Do not modify only the tempo in the manifest to make a full song fit. The tempo and region must describe the actual authored audio.

## Review without the Windows app.

From the repository root, on any platform with .NET 10:

```powershell
dotnet run --project tools/Veda.Render -c Release -- --render assets/soundtracks/demo-void artifacts/demo-preview.wav
```

Replace the soundtrack path with your folder. This writes an 84-second walkthrough with state requests every 12 seconds. Listening to that file lets you evaluate arrangement quality before connecting gameplay detection.

If the renderer reports clamped samples, reduce the authored gains or source level. The last-stage peak guard is not a substitute for mixing.

## Music records.

Keep the generation date, source/export files, subscription records, and current usage terms with your production assets. Before a commercial release, verify the rights for the exact use: distributing editable/looped audio inside an app and allowing users to record or stream the resulting soundtrack. That review remains a release task; no Suno rights are inferred or granted by this repository.
